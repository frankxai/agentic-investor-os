# README Quality Notes

These notes define the quality bar for public Agentic Investor OS docs, examples, and templates.

## Public-Safe Standard

Public materials should contain:

- General workflows.
- Fictional or placeholder examples.
- Source and evidence discipline.
- Approval gates.
- Open questions and risks.
- Human-review language.

Public materials should not contain:

- Live deal, company, founder, customer, fund, LP, or partner details.
- Confidential strategy, terms, pipeline, valuation, cap table, or internal decision records.
- Credentials, private paths, private URLs, or unpublished IP.
- Outcome promises, certainty language, or performance claims.
- Legal, tax, accounting, securities, compliance, or investment conclusions.

## Claim Quality

Use this table before adding or publishing a claim.

| Claim Type | Required Treatment | Example Status |
|---|---|---|
| Product capability | Link to demo, screenshot, docs, or mark missing. | Source-linked or missing. |
| Customer adoption | Require approved source and confidentiality review. | Verified only after approval. |
| Market size | Treat as a question unless source and method are cited. | Source-linked or inferred. |
| Technical risk | Attach architecture, dependency, security, or review notes. | Draft until reviewed. |
| Financial model input | Record source and caveat; do not draw regulated conclusions. | Source-linked or missing. |
| Legal or compliance issue | Route to qualified review. | Escalated. |

## Template Quality Checklist

Each template should:

- State purpose and audience.
- Ask for source, date, owner, and evidence status.
- Include missing-information fields.
- Include risk and approval sections.
- Separate facts, assumptions, and questions.
- Avoid scoring systems that imply automated decisions.
- Avoid language that directs a buy, sell, fund, reject, or hold decision.

## Workflow Quality Checklist

Each workflow should:

- Start with scope and confidentiality.
- Define the human decision owner.
- Assign lanes to named agents or roles.
- Capture source freshness.
- Produce an artifact that can be reviewed.
- End with explicit approval gates.

## Evidence Review Questions

- What source supports this statement?
- How fresh is the source?
- Is the source public, private, or restricted?
- Is the statement a fact, assumption, inference, or open question?
- Who owns the next action?
- Which approval gate applies before sharing?

## Risk Language

Prefer:

- "Evidence needed."
- "Open question."
- "Human review required."
- "Potential risk."
- "Decision criterion."
- "Support option."

Avoid:

- "Certain."
- "Certain outcome."
- "Proven winner."
- "No risk."
- "Should invest."
- "Legally compliant."
- "Tax efficient."
- "Accounting approved."

## Release Review

Before handoff, run validation and scan changed files for:

- Confidential information.
- Private paths.
- Missing approval gates.
- Unsupported claims.
- Regulated conclusions.
- Broken markdown tables.
- Public examples that look like real private records.

If a public-safe claim cannot be supported, keep it as an open question.
